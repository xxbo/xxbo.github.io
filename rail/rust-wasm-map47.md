# MAP47：满意度、经营财务及共享时钟 Rust 化

## 实现

新增 `rust/rail-routing/src/operations.rs`，通过 `operations_abi = 1` / `operations_run` 的 f64 数据帧调用，适配层为 `rail/operations-wasm.js`。继续使用同一个 WASM 实例与有界回收策略，保留现有存档结构；模块重建后直接从当前镜像输入恢复，不回退到另一套JS算法。

- 满意度：一次展开全线网服务，批量传入元数据；Rust完成连通可达站、设施步行覆盖、负载/候车/速度/绕行、七项评分、指数平滑及认知/信任和反馈计数衰减。查询接口保持只读。JavaScript提供服务/票价和设施类型元数据，读取最终评分作需求倍率。
- 经营财务：成本、发展金、余额、欠费、分线固定成本分摊、额度限制、借款、日计息、自动还本付息、提前结清、停运判断全部由Rust计算。分线成本与经营结算共用一个批次。JS投影视图、原贷款对象和最多80条中文流水；建设报价、车辆购买/回收和旧版本返还继续属于JS建设事务。
- 共享时钟：同一个原生内核决定下一步长/时刻、残余区间、贷款到期切分、乘客分钟生成门控和余数。管理层直接执行单个乘客步骤，删除管理层再进入乘客层步进循环的双层结构。直接调用乘客推进时，一次取得时钟议程再执行各步骤。保留小于等于1e-9分钟的原有跳过行为、到期容差和浮点运算顺序。

默认加载 `rail-core-v7.wasm`，392999字节，SHA256：
`66c70628d598548ff8af34a73b9abe6a41fd3b9f529b05f8c1a6fb56bb50a6cc`。
旧v1–v6资源保留供旧缓存页面加载。页面、两个Worker和新适配器的缓存版本已同步。隐藏的运行诊断展示经营时钟调用数与ABI版本。

## 顺序与边界

每个乘客步骤仍保持：前进时刻 → 刷新配车 → 分钟门控/满意度 → 到达抽样 → 发车 → 列车运动/队列/原生事件统计 → 经营结算/分线成本 → 城市生长 → 运营观察。
贷款结算在同一个经营原生批次内完成；城市生长与运营观察目前只读取所需经营/统计值，不修改贷款或现金。欠费停止在与旧版相同的时刻。

这是共享时钟和原生经营反馈链，尚不是一次WASM调用推进几十分钟的完整原生游戏循环。每0.1分钟仍有队列和经营两个原生批次，JS仍负责城市生长、服务元数据更新、日内到达曲线、日归档、异步重算、视图/存档镜像和诊断采样。下一步应统一这些原生状态所有权与长区间执行，而不是继续增加零散小函数跨语言调用。

## 验证

- Rust 14项单元测试；固定Rust1.99.1、wasm32构建并进行字节一致性检查。
- 轨道游戏语法检查与46组回归套件。
- 新增完整MAP46冻结调用链，仅放在测试夹具。261组直接事件对照、497个完整运行检查点，比较世界、列车/队列快照、出行定义以及JSON字段顺序；包含整数/加权乘客、分线编辑、跨日/分时边界、模块强制回收。
- 新增满意度只读查询、零时长刷新、遗留模型反馈、学校/医院覆盖、分数衰减与平滑、贷款到期/逾期、欠费、余额耗尽、多笔贷款错开到期、提前结清、无效金额/额度、微小余数等对照。
- 12小时连续游戏、12次重算、12次JSON存档往返，乘客守恒；生成6168人、完成6044人。观测JS堆峰值23.73MiB、进程RSS峰值256.42MiB，耗时8441ms。压力用例包含预测和存档，不等同于纯运行基准。

## 同轮经营仿真基准

命令：`node scripts/benchmark_rail_operations.cjs 5` 和 `... 7`。
每个版本在独立进程中使用相同初始世界/需求，预热30游戏分钟，再测5段各120游戏分钟，取中位数；包含乘客、满意度、财务、存档所依赖的镜像投影。两版完整最终世界/快照/出行定义校验值一致。耗时是计算吞吐量，不代表浏览器帧率；RSS包含Node/V8和WASM，并非浏览器总内存。
