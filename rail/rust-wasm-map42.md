# MAP42：需求数值层迁入 Rust

## 本批完成

`rust/rail-routing/src/demand.rs`接管四类运算：

- 重力模型OD矩阵生成、IPF行列配平、有限迭代后的行预算约束。
- 步行/骑行与机动车嵌套Logit出行选择。
- 按班次频率选择可接受路径集合、期望等待与各路径份额。
- 轨道容量汇总、断面负荷、路径限流、实际承运量及分线客流汇总。

生产`demand-model.js`对应的JavaScript循环实现已删除。`demand-kernels.js`承担二进制编码、API默认值兼容及对象还原；它提供模型输入，不维护另一份计算算法。冻结MAP41需求模型位于`scripts/fixtures/rail-map41-demand.cjs`，只供回归和基准使用，部署只复制rail目录。

本批属于需求核心第一批。接驳面积采样、分区归集、枢纽市场与外部出行预算、出行分组合并仍由现有JS协调；连续列车/乘客、城市生长、财务与展示模块沿用原实现。下一批适合将接驳、枢纽和最终分组分配一起下沉，减少每个OD组往返WASM的次数，再继续迁移运行状态。

## ABI与数据所有权

沿用寻路ABI 1，新增需求ABI 1。数值核与寻路共享一个实例和输入/输出暂存区，JavaScript单线程同步调用；内存超过64MiB的已完成任务触发实例重建，单实例最大256MiB。重建会清理当前激活图标记，下一次寻路重新装载，已返回路径与矩阵仍然有效。

| 导出 | 输入/输出 |
| --- | --- |
| `demand_ipf` | 矩阵、目标行列和迭代条件 → 矩阵、误差、迭代次数 |
| `demand_distribution` | 分区中心/面积/活动量与出行预算 → 三类目的OD及诊断 |
| `demand_mode_scalar` | 10个标量 → 铁路选择份额；避免每次创建传输缓冲区 |
| `demand_strategy` | 候选路径摘要 → 被选候选索引、成本、频率和份额 |
| `demand_capacity` | 交路班次/定员/轨道与路径需求 → 轨道流量/负荷、承运量、分线流量 |

长期缓存的矩阵由JS拥有的ArrayBuffer承载，内部分区矩阵使用该缓冲区的不重叠子视图，避免再次复制。短小路径策略在同步读取窗口中立即投影成普通JS对象，随后释放Rust输出；公共返回值不暴露WASM内存视图。策略输入暂存区重复使用，大于64KiB的临时输入在使用后回收。

为逐项保留原有浮点结果，WASM仅导入`rail_math.exp/log/hypot`三个标准数学原语，由当前浏览器的Math函数提供；模型决策和计算循环在Rust。这样避免Rust libm与浏览器Math产生末位舍入差异。新增算法未依赖DOM、时钟、随机源、网络或JS模型回调。

## 对照与连续性

新增MAP42门槛采用deepEqual/严格相等，不以误差容忍替代：92组矩阵，1200组方式选择，800组路径频率策略，7组完整需求场景；覆盖零人口、零目的地、停运、严重拥挤、同一结果在实例回收后继续使用、非法尺寸/陷阱恢复。50组容量分配对照额外核验字段值和JSON键顺序。另有2小时反复预测接入与存档恢复，校验实时乘客守恒。

所有41组回归通过，保留原MAP41的2965组路径对照、6000档案完整需求对照和MAP39的35组展示HTML哈希。

12个游戏小时、10线25站、6000出行组合，每小时重算和存档往返：生成6168、完成6044，12次守恒和恢复检查均通过。GC后JS堆首小时25.96MiB、第12小时26.66MiB，最高26.72MiB；进程峰值RSS264.93MiB。本机墙钟约9.6秒。这是合成模拟检查，JS堆不涵盖WASM/浏览器总内存。

浏览器验收检查大湾区已有3线12站存档的自动恢复、持续运行、后台重算、运营中心、保存/导出与刷新；诊断展示数值核调用计数及WASM线性内存。

## 性能口径

独立Node进程，预热后3次中位数；200分区OD、1200次方式选择、800次策略以及10线25站完整预测。两份输出的SHA256相同：`ea19bf619a09a213a2411b6a9aa49aa6e2e51462fda9e63c2da96c48c90402b0`。

| 测量项 | MAP41 | MAP42 |
| --- | ---: | ---: |
| OD矩阵 | 15.29ms | 10.52ms |
| 1200次方式选择 | 0.49ms | 0.39ms |
| 800次路径策略 | 0.84ms | 2.33ms |
| 完整预测 | 648.10ms | 675.09ms |
| 进程峰值RSS | 226.23MiB | 235.48MiB |
| 实例线性内存 | 1.25MiB | 3.625MiB |

OD子任务耗时下降约31%，但小粒度策略存在跨边界及对象还原开销，完整预测该场景约慢4%。此批以计算所有权迁移和精确性为门槛，不据此宣称整页提速或降低总内存。后续采用整段批量分配，收敛JS/WASM往返；继续分开记录JS堆、ArrayBuffer、WASM线性内存与RSS。
