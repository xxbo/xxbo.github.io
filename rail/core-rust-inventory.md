# 核心 Rust 迁移盘点（MAP53）

最新逐函数审计与优先级见 [核心迁移审计](rust-migration-audit.md)。

盘点依据是当前默认新游戏（routeModel 9）的实际调用链，按12个能力域划分。MAP47在原有六类原生计算上加入满意度/需求反馈、经营财务/借贷和共享步进时钟；MAP48完成连续闭环的时序规则前置迁移：曲线、连续采样倍率、整数/加权到达、配车分配及运行服务刷新。MAP49进一步把队列/统计与经营结算合并为一次原生事务，原生持有连续财务状态并准备下一时钟，日需求改为增量同步。MAP50把满意度/需求反馈→到达采样→发车判断连接为`engine_prepare`原生批次，缓存设施/换乘覆盖，精简运动临时表，并接入保留旧0.1分钟步序的宿主预算批量推进。城市生长、线网/车库编辑、运营诊断仍主要在JS；建设资产计价、服务元数据、归档及宿主编排也仍有JS边界。能力域有部分迁移，不能简单按9/12宣称完整核心已迁移75%。


MAP51进一步将两段热批次融合为`engine_cycle`：默认routeModel 9的实际出行编号、去重注册、列车运行编号及原生状态创建进入Rust，JS只生成保存和展示镜像。`engine_continue`在下一个宿主边界前执行多个0.1分钟小步，列车、队列、统计和财务共用持久状态；默认浏览器运行走专用模拟Worker，使用可转移数值缓冲。分钟/需求门控、发车、城市、诊断、还款切分边界仍由宿主提供下一帧；城市与线网规则尚未整体迁移。历史routeModel 1大规模加权存档保留MAP50流式适配，避免再建立一份庞大身份索引；该兼容路径的计算核仍是Rust，但对象注册和循环继续由JS编排。

MAP52 完成 P0 第一批状态投影优化：默认融合事务输出紧凑列车动作与采样摘要，元数据补齐复用原生准备结果，删除连续子步的整表列车包装分配，并加入跨线程字节诊断。计算结果与 MAP51 完整状态对照一致。JS 完整镜像、每分钟目录扫描和宿主事件边界仍存在；完整运行状态统一与跨边界自主循环继续推进，见 [MAP52](rust-wasm-map52.md)。

MAP53 验收默认模型的 P0：`calendar.rs` 原生服务日历跨分钟及普通发车推进；运行候车、站外、换乘和车厢明细驻留 Worker，前端只保留轻量视图；`runtime_query` 提供站/车详情和运行快照；受控目录以明确修改集合更新，避免逐档案监听器及无变化全表扫描。主线程保留城市/历史、静态定义及外部编辑的临时事务，旧模型/无 Worker 环境使用完整兼容投影。详见 [MAP53](rust-wasm-map53.md)。

## 能力清单

| 能力域 | 当前执行位置 | 依据与剩余边界 |
| --- | --- | --- |
| 1. 寻路、换乘与路径票价 | Rust主计算 | `lib.rs`搜索、堆、路径重建与票价累计；`service-plan.js`仍构建服务图和配置票价。 |
| 2. 步行/接驳、枢纽、OD、方式与容量分配 | Rust主计算 | `world.rs`、`demand.rs`完成整段预测；`demand-world.js`负责输入准备及结果映射。 |
| 3. 乘客到达抽样 | MAP48：Rust曲线/倍率/抽样 | `temporal.rs`负责工作/购物/休闲和枢纽/员工出行的日内曲线；`simulation.rs` op9在同一批次计算满意度/旧模型倍率和整数/加权到达。分钟门控已在MAP47迁入Rust；MAP49由Rust持有日需求向量；MAP53 默认受控目录通过明确修改集合同步，兼容调用保留直接修改扫描。MAP50在同一准备批次中直接使用最新满意度，再采样和判断发车；MAP51在Rust内完成开放服务判断、实际出行去重/编号及原生队列注册；JS按结果建立存档与展示镜像。 |
| 4. 列车调度与运动 | Rust主计算 | `simulation.rs`调度决定、运行与信号；MAP50直接遍历原生列车行计算运动，移除每步20列临时整表；发车判断接入准备批次。MAP48的`temporal.rs`额外负责运行服务刷新、自动/手动投放、交路配车、运行间隔和发车重排；JS仍提供交路展开、路径时长元数据、预测/展示使用的间隔接口及列车视图投影。 |
| 5. 站台/站外/换乘与上下车 | Rust主计算 | `queues.rs`持有队列、车厢乘客、限流、超时、完成出行及票款分摊；JS仍编排结构修改、改签和恢复，并保留运行镜像。 |
| 6. 运营事件统计与客流纪录 | MAP46：Rust事件计算 | `statistics.rs`累计日/分线/车站/分时客流、候车分钟、票款、客运/车辆周转量、滚动小时峰值与客流纪录；JS仍负责日归档、实时查询、成就展示和视图字段投影。 |
| 7. 满意度、信任与需求反馈 | MAP47：Rust主计算 | `operations.rs`批量计算换乘可达/设施覆盖、负载、候车、七项评分、平滑、认知/信任与计数衰减。JS展开服务、提供票价/车辆元数据并记录归档。连续到达链的需求倍率已由MAP48放入原生抽样批次；MAP50的`engine_prepare`串联反馈与采样，`CoverageCache`按节点坐标、设施坐标/规模、站序与可连接状态做精确比较失效，复用设施覆盖结果。`Q.factor`兼容查询接口仍保留。 |
| 8. 财务、贷款和建设资产 | MAP47：Rust经营/借贷，JS建设事务 | `operations.rs`负责经营成本/发展金、分线成本分摊、余额、欠费、额度、借款、利息、自动还款与提前结清；`management.js`/`fleet.js`仍处理建设报价、回收、购车和旧余额版本返还。 |
| 9. 城市生长与系统设施 | JS | `urban-growth.js`、`city-development.js`：用地倾向、开发/升级、设施生成、覆盖和城市发展阶段。 |
| 10. 线网编辑、交路与车库规则 | JS | `network.js`、`service-plan.js`、`fleet.js`：增删站线、曲线、站点合并、直通连接、大小交路/快慢车、规格锁定和配车约束。 |
| 11. 全局时钟及生命周期编排 | MAP53：原生服务日历、跨分钟循环和Worker；生命周期仍有桥接 | `cycle.rs`顺序执行反馈→采样→出行注册→发车/列车注册→运动→队列/统计→经营结算；改签续算结束后才结算。`engine_continue`原生循环到下一个分钟、到达门控、发车、城市/诊断或贷款切分边界，保留每步事件及浮点顺序。MAP53 的 `engine_loop` 内部准备分钟、平高峰配车、到达、发车和经营输入；宿主传入修订后的静态服务元数据，仍处理城市生长、日归档、诊断、重寻路衔接和外部编辑事务。运行明细留在 Worker，前端接收轻量投影与按需快照。 |
| 12. 运营诊断、建议与报警 | JS | `operations-center.js`、`operations-review.js`、`alerts.js`、`network-stats.js`、`insights.js`：断面分析、加减车/交路建议、效果评估、报警及汇总查询。 |

第12项属于业务判断，单独列出，以免把运营中心全部视作纯展示。第6项也不等于统计文件已全部清空：事件累计已迁移，时间归档和查询仍有JS。上述“Rust主计算”均仍经过JS输入/输出适配，并不表示完整仿真已全部由Rust持有。

## 当前性能问题横跨哪些模块

1. MAP53 的默认服务日历已跨分钟及普通发车，城市、历史、诊断及特殊事务仍有宿主边界。两组冻结 MAP52 Worker 基准耗时下降约 27%—33%，应与地图/DOM 渲染和实际帧率分开衡量。
2. 默认 Worker 不再持续复制候车/站外/换乘/车厢明细；地图列车点位、统计摘要、静态出行元数据和城市历史仍在 JS。按需详情、保存与外部编辑会短暂取回明细；同步与旧模型保留完整兼容投影。预测目录和世界快照仍是后续内存优化重点。
3. 结构编辑和撤销仍通过JS世界快照与校验。Rust命令事务将来可替代整份世界对象复制。
4. 实时统计查询、运营建议、SVG/DOM刷新是独立成本；主计算迁移不会自动消除这些开销。
5. 旧模型还保留`engine.js`、`operations.js`及`city.evaluateLegacy`等JS兼容路径。默认新游戏走当前原生路径；兼容清理应与存档迁移单独验证。

地图瓦片加载、拖拽/缩放、DOM/CSS/Canvas渲染、主题、文件选择、IndexedDB和网络请求属于宿主职责，继续保留在JS。存档的读取/写入可以在JS，核心状态验证和快照生成则适合逐步转入Rust。

## 后续七批路线及当前进度

1. **连续仿真闭环**：第1步时序规则已完成（MAP48）；MAP49完成队列/经营事务与部分原生状态整合；MAP50已串联反馈/采样/调度准备，加入覆盖缓存、直接列车行运动与宿主预算批次；MAP51已融合两批次、接入Rust分段跨步循环和模拟Worker；MAP53 已迁入分钟/发车日历并移除默认 Worker 的逐乘客镜像；剩余为城市、归档、改签等业务生命周期。
2. **运行状态统一持有（P0 默认路径已落地）**：候车/站外/换乘/车厢明细留在 Rust，界面按需查询；列车点位与统计保留轻量投影。原生快照恢复运行明细，外部编辑有临时事务投影；完整版本迁移和校验继续归入兼容收尾。
3. **城市生长与设施**：选址倾向、开发升级、人口/就业、系统设施和发展阶段。
4. **线网、交路与车库**：建设命令、站点合并、曲线/环线/跨线校验、规格和配车约束。
5. **建设资产与交易**：建设/回收/购车报价、库存价值、原子扣款与回滚。
6. **运营查询与诊断**：断面/强度、运力与交路建议、效果评估、报警、归档和成就判定。
7. **存档及兼容收尾**：原生快照/恢复校验、版本迁移和容量管理，再清理已替代的生产JS计算。

按可独立验收的小版本推进，保留冻结测试对照；每一批都报告实际边界、耗时和内存，不以文件迁移数量推断性能收益。
