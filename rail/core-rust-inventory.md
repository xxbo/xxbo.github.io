# 核心 Rust 迁移盘点（MAP49）

盘点依据是当前默认新游戏（routeModel 9）的实际调用链，按12个能力域划分。MAP47在原有六类原生计算上加入满意度/需求反馈、经营财务/借贷和共享步进时钟；MAP48完成连续闭环的时序规则前置迁移：曲线、连续采样倍率、整数/加权到达、配车分配及运行服务刷新。MAP49进一步把队列/统计与经营结算合并为一次原生事务，原生持有连续财务状态并准备下一时钟，日需求改为增量同步。城市生长、线网/车库编辑、运营诊断仍主要在JS；建设资产计价、服务元数据、归档及宿主编排也仍有JS边界。能力域有部分迁移，不能简单按9/12宣称完整核心已迁移75%。

## 能力清单

| 能力域 | 当前执行位置 | 依据与剩余边界 |
| --- | --- | --- |
| 1. 寻路、换乘与路径票价 | Rust主计算 | `lib.rs`搜索、堆、路径重建与票价累计；`service-plan.js`仍构建服务图和配置票价。 |
| 2. 步行/接驳、枢纽、OD、方式与容量分配 | Rust主计算 | `world.rs`、`demand.rs`完成整段预测；`demand-world.js`负责输入准备及结果映射。 |
| 3. 乘客到达抽样 | MAP48：Rust曲线/倍率/抽样 | `temporal.rs`负责工作/购物/休闲和枢纽/员工出行的日内曲线；`simulation.rs` op9在同一批次计算满意度/旧模型倍率和整数/加权到达。分钟门控已在MAP47迁入Rust；MAP49由Rust持有日需求向量，JS扫描直接修改并仅同步差异；JS仍映射出行定义、判断开放服务及投影抽样结果。 |
| 4. 列车调度与运动 | Rust主计算 | `simulation.rs`调度决定、运行与信号；MAP48的`temporal.rs`额外负责运行服务刷新、自动/手动投放、交路配车、运行间隔和发车重排；JS仍提供交路展开、路径时长元数据、预测/展示使用的间隔接口及列车视图投影。 |
| 5. 站台/站外/换乘与上下车 | Rust主计算 | `queues.rs`持有队列、车厢乘客、限流、超时、完成出行及票款分摊；JS仍编排结构修改、改签和恢复，并保留运行镜像。 |
| 6. 运营事件统计与客流纪录 | MAP46：Rust事件计算 | `statistics.rs`累计日/分线/车站/分时客流、候车分钟、票款、客运/车辆周转量、滚动小时峰值与客流纪录；JS仍负责日归档、实时查询、成就展示和视图字段投影。 |
| 7. 满意度、信任与需求反馈 | MAP47：Rust主计算 | `operations.rs`批量计算换乘可达/设施覆盖、负载、候车、七项评分、平滑、认知/信任与计数衰减。JS展开服务、提供票价/车辆元数据并记录归档。连续到达链的需求倍率已由MAP48放入原生抽样批次；`Q.factor`兼容查询接口仍保留。 |
| 8. 财务、贷款和建设资产 | MAP47：Rust经营/借贷，JS建设事务 | `operations.rs`负责经营成本/发展金、分线成本分摊、余额、欠费、额度、借款、利息、自动还款与提前结清；`management.js`/`fleet.js`仍处理建设报价、回收、购车和旧余额版本返还。 |
| 9. 城市生长与系统设施 | JS | `urban-growth.js`、`city-development.js`：用地倾向、开发/升级、设施生成、覆盖和城市发展阶段。 |
| 10. 线网编辑、交路与车库规则 | JS | `network.js`、`service-plan.js`、`fleet.js`：增删站线、曲线、站点合并、直通连接、大小交路/快慢车、规格锁定和配车约束。 |
| 11. 全局时钟及生命周期编排 | MAP47：Rust共享步进/分钟门控，JS宿主编排 | 同一个原生内核计算0.1分钟步长、残余时间、下一时刻、贷款到期切分和乘客生成分钟门控/余数；管理层直接执行单个乘客步骤，去除嵌套步进循环。MAP48补齐日内权重、配车和运行服务刷新规则；MAP49的`engine.rs`把队列、统计、经营与下一时钟连接；常见连续0.1分钟请求复用时钟结果。JS仍编排调度/采样、城市生长、诊断采样、异步重算和视图投影。 |
| 12. 运营诊断、建议与报警 | JS | `operations-center.js`、`operations-review.js`、`alerts.js`、`network-stats.js`、`insights.js`：断面分析、加减车/交路建议、效果评估、报警及汇总查询。 |

第12项属于业务判断，单独列出，以免把运营中心全部视作纯展示。第6项也不等于统计文件已全部清空：事件累计已迁移，时间归档和查询仍有JS。上述“Rust主计算”均仍经过JS输入/输出适配，并不表示完整仿真已全部由Rust持有。

## 当前性能问题横跨哪些模块

1. MAP49已消除每0.1分钟独立队列和经营调用的边界，以一次`engine_step`顺序执行队列/事件统计和经营结算；改签续算完成后再结算，财务/贷款/分摊元数据持久化。步长、分钟门控和财务决策已原生化，但尚未把整段连续仿真收进一次长区间Rust调用。城市/诊断回调、原生模块间的调用顺序及视图同步仍需宿主编排。日内曲线和运行服务刷新已迁入Rust，但还通过独立批次调用。
2. 运行数据同时存在于Rust与JS镜像中。列车、队列、统计字段仍需投影，保存也依赖当前JS格式。
3. 结构编辑和撤销仍通过JS世界快照与校验。Rust命令事务将来可替代整份世界对象复制。
4. 实时统计查询、运营建议、SVG/DOM刷新是独立成本；主计算迁移不会自动消除这些开销。
5. 旧模型还保留`engine.js`、`operations.js`及`city.evaluateLegacy`等JS兼容路径。默认新游戏走当前原生路径；兼容清理应与存档迁移单独验证。

地图瓦片加载、拖拽/缩放、DOM/CSS/Canvas渲染、主题、文件选择、IndexedDB和网络请求属于宿主职责，继续保留在JS。存档的读取/写入可以在JS，核心状态验证和快照生成则适合逐步转入Rust。

## 后续顺序

| 顺序 | 迁移内容 | 完成条件 |
| --- | --- | --- |
| MAP46（已落地） | 运营事件统计与纪录累计 | 直接在队列批次内计算，热循环不新增独立统计WASM调用；保持原有浮点累计顺序与存档结构。 |
| MAP47（已落地） | 满意度/需求反馈 | 所有线路一次批量评估，覆盖/候车/拥挤等规则、衰减和平滑由Rust执行；逐检查点完整状态一致。 |
| MAP47（已落地） | 经营/借贷与共享步进时钟 | 费用、收入、补助、计息、还款、额度、欠费边界与分钟门控原生化；保留旧存档形状及浮点运算顺序。 |
| MAP48（第一批·第1步已落地） | 补齐连续闭环时序规则 | 日内曲线、需求倍率、两种到达模型、自动配车、运行服务刷新进入Rust；倍率与曲线直接在抽样内核内计算。 |
| MAP49（第一批·第2步部分落地） | 原生连续循环及状态整合 | 在同一原生状态中串联列车、队列、统计、满意度、财务；MAP49已完成独立队列/经营批次合并、财务状态复用、下一时钟预计算与日需求增量同步；调度、到达采样、满意度及城市/诊断回调仍由宿主串联。 |
| 随后（第一批·第3步） | 长区间推进与执行预算 | 逐步扩大一次推进区间，按执行预算/宿主事件边界返回；验证编辑中断与恢复，再评估专用仿真Worker。 |
| 后续 | 城市发展、建设与交路命令 | 原生状态事务、校验和派生指标，逐步取消大体量JS镜像与整份世界复制。 |
| 后续 | 运营诊断及查询 | 从Rust状态批量提取断面/负载/建议，按界面刷新频率返回结果。 |

每一步同时验收算法一致性、端到端耗时、内存和存档连续性。能力域计数用于排期，性能完成率以测量为准。

## 后续七批路线及当前进度

1. **连续仿真闭环**：第1步时序规则已完成（MAP48）；MAP49完成队列/经营事务与部分原生状态整合；继续收拢调度/采样/满意度，再做长区间与执行预算。
2. **运行状态统一持有**：精简JS全量列车/队列/车内乘客镜像，界面按需获取摘要与变化。
3. **城市生长与设施**：选址倾向、开发升级、人口/就业、系统设施和发展阶段。
4. **线网、交路与车库**：建设命令、站点合并、曲线/环线/跨线校验、规格和配车约束。
5. **建设资产与交易**：建设/回收/购车报价、库存价值、原子扣款与回滚。
6. **运营查询与诊断**：断面/强度、运力与交路建议、效果评估、报警、归档和成就判定。
7. **存档及兼容收尾**：原生快照/恢复校验、版本迁移和容量管理，再清理已替代的生产JS计算。

按可独立验收的小版本推进，保留冻结测试对照；每一批都报告实际边界、耗时和内存，不以文件迁移数量推断性能收益。
