# MAP44：连续模拟第一批 Rust 内核

## 本批接管

现代游戏的 `passengers.tick` 使用 Rust 的调度、运行与分配决定，JS 接收有序结果、保留现有展示对象及记账接口。

| 模块 | 本批状态 |
| --- | --- |
| 交路发车 | Rust：运营时间、列车/母线投放上限、方向配额、环线限制、下一班计划 |
| 列车运行 | Rust：移动进度、到站/停站、信号阻塞、轨道间隔、环线续跑/收车、车公里与车辆支出增量 |
| 上车分配 | Rust：排队顺序、过期候车、快车目的地、方向与环线校验、容量分配 |
| 整数到达 | Rust：OD权重、全局余数、LCG随机数、系统抽样和尾数分配；小OD不逐个取整 |
| 乘客队列与事件 | JS：进站限流、站外候车、换乘就绪、下车、改签、完成出行及事件回写 |
| 周边模型 | JS：满意度反馈、财务/成就/分时记录、城市生长、存档、地图绘制 |

旧版对应的发车判定、移动状态推进、上车选择和整数抽样循环已从生产 `passengers.js` 删除。冻结版本为 `scripts/fixtures/rail-map43-passengers.cjs`，仅供回归与基准。独立的旧版 `operations.advance` 兼容 API 仍保留；实际游戏连续客流使用 `passengers.advance`。

## 状态与事件顺序

保留0.1游戏分钟步长、调用顺序和浮点运算顺序。每步仍依次更新配车、换乘就绪、生成需求、发车、按列车顺序推进并处理上下车。Rust只返回决定，不调用JS的游戏模型；现有满意度、票款、乘客公里和成就事件按原顺序落账。

新增 `simulation_abi=1`，统一 `simulation_run` 数值协议：

- 操作0：无状态列车状态批处理，亦供内部复用。
- 操作1：候车队列摘要 → 删除/超时/上车命令。
- 操作2：按组系数与OD档案 → 总期望、余数、新随机状态、实际到达的稀疏档案/人数。
- 操作3：既有车队及待发交路 → 发车决定/下班时间。
- 操作4：持续运行状态。首次同步列车、轨道和停站元数据；后续同步时间与信号释放时刻，由Rust保留移动状态。

运行实例只保留一份当前线网的数值状态。切换存档、实例重建、线网/车队变化、跨分钟配车更新后，从当前JS对象恢复同步；多个运行实例交替调用通过身份号隔离。轨道、停站布局按列车/计划对象WeakMap缓存，列车退出后允许GC回收。缓存不写入存档，不改变原有存档格式。队列、档案ID、列车ID与原对象保持一致。

结果数组由JS独立拥有，上下车或临时改签过程中再次调用WASM，甚至发生实例重建，当前批次仍有效。WASM发生陷阱后清理实例标记，下一步从现有运行对象同步。最大线性内存仍256MiB，超过64MiB的任务完成后重建。

## 验证

- 1082个逐步运行检查点严格对照完整状态、档案、收入与满意度记录。
- 1196个独立抽样对照，含151056个微小OD、系数变化、随机数回绕和全局余数。
- 高峰/平峰、开收车、午夜、环线收车、直达/快慢车、改价/减车重算、两个运行实例交替、JSON恢复、强制实例重建及异常恢复。
- 项目语法检查与43个回归套件；Rust9个单元测试。
- 12个模拟小时、12轮重算和12次存档往返；生成6168、完成6044，候车/在途/完成/取消守恒；采样JS堆峰值23.38MiB。

## 性能实测与下一步

独立Node进程，同一10线/25站、72列在线的工作负载，预热10个游戏分钟，再测三段60个游戏分钟取中位数。最终状态、档案、满意度记录的SHA256两组均为 `9c9a9db4078e112a3c959d3e387bcb23bb531a695f2ba7b30dd6c124741976de`。

| 指标 | MAP43 JS连续模拟 | MAP44 混合运行内核 |
| --- | ---: | ---: |
| 推进60个游戏分钟 | 103.22ms | 148.85ms |
| 进程峰值RSS | 120.24MiB | 126.49MiB |
| GC后JS堆 | 20.38MiB | 20.45MiB |

当前小线网纯模拟基准约慢44%；首版每帧重新编码元数据已改为持续状态和布局缓存，但队列/事件仍在JS，跨语言分段及同步开销仍然存在。这批完成运行决定接管和结果一致性，尚未取得连续模拟提速，FPS与浏览器总内存需要独立测量。MAP43整段需求预测的收益与本表的连续模拟阶段是不同工作负载。

下一批应将候车/站外/换乘队列、上下车、到达生成和事件日志一起放入原生状态，按一整个模拟区间返回事件批次与展示快照，减少逐步同步和逐次上车调用。随后再迁入满意度/财务/城市时钟，最终让JS集中处理展示、输入和存储。

```sh
node scripts/build_rail_wasm.cjs --check
node scripts/run_rail_tests.cjs
node scripts/benchmark_rail_simulation.cjs
node --expose-gc --max-old-space-size=512 scripts/stress_rail_memory.cjs
```

资源版本为 `rail-core-v4.wasm?v=44`；保留v1–v3供已打开的旧页面使用。页面与需求/运营Worker同时升级装载路径。
