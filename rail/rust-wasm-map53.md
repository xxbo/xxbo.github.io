# MAP53：P0 原生服务日历、运行明细与按需快照

## 验收范围

默认 routeModel 9、专用模拟 Worker 路径完成 P0 主线。分钟准备、普通发车和运行结算在 Rust 中连续推进；候车、站外、换乘和车厢乘客明细不再在主线程常驻第二份对象。地图保留在线列车的轻量点位/载客投影，统计与运营中心使用平台汇总。CPU 和状态对照见下方；这不表示城市、编辑、历史和全部兼容路径都已 Rust 化。

## 原生日历

新增 `calendar.rs::engine_loop`，按修订后的静态服务元数据持有时长、运营窗、平高峰配车、发车时刻/间隔、单/双向环线停站。每个原有 0.1 分钟小步仍按反馈→到达→发车→列车/队列→统计→经营顺序执行，共用 `cycle.rs`，没有第二套仿真规则。服务日历内部更新分钟、配车、反馈和采样输入，不再为普通分钟/发车返回主线程准备。

保留时间预算与步数上限。统计槽/日切、城市和运营评估、贷款分割、元数据缺失和改签事务有明确让出理由；未知出行模板先请求再提交，保持原来的随机流、事件和浮点顺序。退役列车及超过 45,000 条实际出行定义时使用已有原生短批次桥接，便于 P1 接续迁移其生命周期。

## 状态、查询和保存

- 默认 Worker 的队列协议 3 省略逐 cohort 的 UI 赋值；平台人数、站外人数、换乘人数及计数形成轻量视图。主线程持续运行时 `queues / outside / transfers / train.passengers` 不保留真实乘客明细。
- `runtime_query` 按完整运行快照、运行摘要、所选车站、所选列车查询。保存所需队列/车厢和列车动态、采样时钟、轨道闭塞数据由原生读取后映射为原有 JSON。主线程城市/历史/静态配置仍按既有格式保存，IndexedDB 与文件操作留在浏览器。
- 原生运动协议 11 重用已有动态状态和闭塞释放时间，避免把 UI 点位反向当作运行真值。环线圈数、最近区间及未发车字段的缺失语义保持兼容。
- 编辑/重算前等待当前事务并读取完整原生状态，再运行既有迁移；编辑后、尚未重同步时的保存使用已经迁移的事务状态，避免旧原生快照覆盖新编辑。下一次原生提交后释放临时明细。归档、改签和大目录重编号仍按 P1/P2 分批迁移。
- 活跃原生状态启用保护，避免超过旧回收阈值时直接丢弃唯一运行状态；结构重建及新游戏释放旧工作区/线程。Worker 构造失败时先切换为相同 Rust 内核的完整兼容投影，保留安全重建能力。

历史 routeModel 1 保留原来的流式宿主桥接，避免建立巨大第二份原生身份索引；同步测试/工具接口也保留完整投影。原有 `snapshot` 用于完整投影；默认浏览器保存使用 `snapshotAsync`，编辑使用 `materializeAsync`。

## 需求修订

受控运行目录通过 `setDaily` 记录修改索引与修订号；无变化分钟不扫描全目录。结构性变化替换目录。`SIM.trackCatalog` 将目录交由明确修改集合管理，`RailPassengers.setDaily(runtime, index, value)` 同时更新展示总量。兼容调用未接管目录时仍检测直接字段修改；自定义动态 getter 使用短批次兼容路径。

实现未使用逐档案 accessor / Proxy。早期监听器版本使小场景 JS 堆增加约 6 MB，已撤除；最终受控目录只保留紧凑数值表和修改集合。151,056 条目录的冷启动编码逐段追加，避免大数组 spread 导致调用栈溢出。

## 对照与压力验证

- 69 项 JS 回归与语法检查；21 项 Rust 单元测试。
- 冻结 MAP52 的 19 个 JS 模块与 v12 二进制作为独立基线。新测含 200 个预算/边界检查、80 个真实 Worker 检查、400 个拥挤/改签/退役列车检查，以及原生快照/查询/JSON 恢复、编辑后立即保存、大目录整理和无 Worker 降级检查。
- 30 个原生状态检查覆盖受管/非受管、双向/单向正反环线、普通/快车/直达、平高峰与 0.1 分钟内部还款切分。查询读出的完整状态与冻结版一致；修改 UI 进度不改变原生保存值。
- 60,000 条受控需求连续 60 个无变化分钟零额外目录读取；两条修改只同步两项；原生回收后正确全量重载。151,056 条冷目录可启动日历并跨分钟，原生摘要/保存成立。
- 12 游戏小时、12 次重算与 JSON 校验/恢复：生成 6,168、完成 6,044，守恒通过；采样 JS 堆峰值 24.83 MiB，Node 进程 RSS 峰值 312.86 MiB，耗时约 8.6 秒。RSS 包含整个进程及 Worker，与早先同步压力测试不直接作内存优劣比较。
- 浏览器读取 MAP52 旧档，正常继续运行；运营中心、所选站候车/目的地、编辑、立即保存、刷新恢复及再次运行均已验证。

## 固定真实 Worker 基准

独立 Node 进程，交替顺序两轮，30 游戏分钟预热后 5 × 30 分钟。保留相同小步、客流与完整状态，时间为批次中位值，传输为测量窗口累计。完整快照按对象键规范化后 SHA-256 一致，数组/事件顺序保留；基准不包含浏览器地图和 DOM 渲染，不表示实际 FPS。
