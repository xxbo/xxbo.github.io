# MAP57：P1-1 原生历史生命周期

当前日及30日历史由 Rust `lifecycle.rs` 随统计状态持有；原生循环自主跨越07:00日界，归档、成熟度快照、小时维护、当前日重置与财务日重置属于同一时序。宿主保留兼容 JSON 投影视图，保存前从原生查询当前日及历史，不以滞后的界面副本覆盖权威历史。显式外部统计/财务修订先同步，再接续原生循环。

`daily.rs` 执行日报聚合，界面仅附加名称、颜色和本地化排序。冷结构 ABI 保留字段顺序、未知附加字段、undefined、NaN/Infinity及正常Unicode。无效独立代理码元不在游戏字段输入约定内。

## 验证

73项JS回归、29项Rust单元测试通过；独立发布组合校验通过。新增长期回归对照冻结MAP56的95个完整世界、原生历史查询及完整运行存档，连续32天并验证30日裁剪。已有Worker跨日/债务/统计修订回归仍严格一致。

## 双基线性能

连续运营核心，30分钟预热、5×30分钟测量，两轮反向顺序独立进程；严格比较完整世界与存档。单位：耗时ms、RSS MiB、事件循环最大延迟ms。测量具有运行环境波动；不宣称稳定吞吐提升。

| 场景 | 上版MAP56 → MAP57 Worker耗时 | 固定纯JS → MAP57 Worker耗时 | 纯JS → Worker峰值RSS | 纯JS → Worker延迟 |
|---|---|---|---|---|
| 10线/25站 | 64.165 → 76.693（+19.52%） | 43.307 → 79.295（+83.10%） | 104.24 → 164.68 | 59.02 → 2.80 |
| 14线/49站 | 120.416 → 127.356（+5.76%） | 155.430 → 123.532（-20.52%） | 176.01 → 278.68 | 202.46 → 6.62 |

相对上一版出现负收益，历史副本与统计同步增加了原生工作；热循环输入输出字节和请求数保持一致。小场景相对纯JS仍更慢，较大场景的累计吞吐有收益，RSS仍明显更高。主线程隔离改善仅由Node延迟探针支持，不等同于浏览器FPS提升。完整CPU、JS堆、WASM和传输原始数据见 [performance-map57.json](performance-map57.json)，复现沿用 [基线约定](performance-baselines.md) 及 `benchmark_rail_worker57.cjs`。
