# MAP52：P0 第一批——压缩投影与复用原生准备状态

## 实现

- 新增 `projection.rs`，按列车动作只输出 UI 所需字段，空闲动作省略。距离和车辆支出继续在原生队列、统计和财务内结算，无需回传后再次丢弃。队列结果协议为版本 2，保留版本 1 供旧桥接和独立接口使用。
- `engine_cycle` 与 `engine_continue` 使用紧凑投影，JS 按原生 UID 更新已有列车；删除每个连续子步建立 `{t,l}` 整表的分配。输出缓冲按所需大小预分配。
- 到达事件已在原生注册/入队，融合事务只回传四值采样摘要。原生补齐出行模板的分批请求复用待提交准备结果和原采样时间，宿主后续请求不重复发送准备输入；统计帧保持同一事务。
- Worker 诊断累计输入/输出字节、请求及最大缓冲大小；内存面板显示运动压缩率、原生保留到达明细和传输量。
- 默认资源为 `rail-core-v12.wasm`，页面 MAP52。历史 v11 资源保留供冻结 MAP51 对照；存档格式不变。

## 验证

62 项 JavaScript 回归及语法检查、19 项 Rust 单元测试通过。新增 288 个完整状态对照、200 个预算/事件边界对照、80 个真实 Worker 对照、400 个拥挤/重算/移除/改签/重建状态对照；基线使用冻结 MAP51 JS 与 v11 原生二进制，避免用新代码充当旧版预期。

2,600 模板冷启动测试：目录只扫描 2,600 项；三次元数据请求后两次准备输入均为零；到达明细 5,200 个数值留在原生；非零生成、队列与乘客守恒成立。另完成 12 游戏小时压力场景（12 次重建、12 次保存），生成 6,168、完成 6,044，守恒通过；采样 JS 堆峰值 24.35 MiB、进程 RSS 269.65 MiB。浏览器恢复 MAP51 存档、立即保存、刷新恢复并继续运行，今日完成出行持续增长。

## 固定基准

真实 Node Worker，独立进程，交替两轮，30 分钟预热后 5 × 30 游戏分钟，保留 0.1 分钟步序；不含浏览器渲染。时间为两轮批次中位值，字节是测量窗口累计。

两场景请求次数分别保持 1,539 / 1,163，完整状态 SHA-256 分别一致为 `260b0f9a9f2aba5aaa7001eecda40caed7bc6043ed67bd0d2abdd4a520e1baa6` / `a058a6dfda5867f7a996e058ff9c2552e7d74c2eb155b459a8a6ff638ec058f5`。较大场景部分运行与回归重叠，计时存在环境噪声；传输字节更直接反映本批收益。

同步 10 线 / 25 站场景（30 分钟预热，5 × 120 分钟）中位 254.083 → 241.715 ms，完整状态哈希一致，JS 堆 22.15 → 21.44 MiB，RSS 基本持平。没有据此推断实际 FPS 或整体内存问题已解决。
