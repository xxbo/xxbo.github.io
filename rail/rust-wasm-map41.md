# MAP41：Rust / WebAssembly 寻路核心

本页记录MAP41迁移边界；当前核心构建与后续需求迁移见 [MAP42](rust-wasm-map42.md)。

## 迁移边界

生产 `service-plan.js` 和 `engine.js` 中的 JavaScript 堆、状态搜索与路径选择实现已删除，两个入口统一调用 `routing-wasm.js`。普通/区间/快速/直达/跨线/环线寻路、换乘等待、方向限制、路径累计票价、旧版公司票价及直通折扣均在 `rust/rail-routing/src/lib.rs` 中计算。JavaScript 负责把现有交路图编码为二进制数组、映射字符串ID、还原现有路径对象及协调加载。

这一步只迁移寻路。交路图构造、OD生成/分配、城市生长、连续列车/乘客模拟、满意度、财务、存档协调和前端仍保留原模块；各部分后续逐批替换。界面与存档格式保持兼容，主线程备用预测同样调用WASM寻路。

测试对照位于 `scripts/fixtures/rail-map40-routing.cjs`、`rail-map39-paths.cjs`、`rail-legacy-paths.cjs`，不会复制到公开站点。运行时没有旧JS寻路开关或算法回退分支。

## 数据与内存

- 目标 `wasm32-unknown-unknown`，Rust 1.99.1，零第三方crate；浏览器与Node使用同一个WASM二进制。
- ABI 1：输入/输出采用Float64Array，整数索引在32位精确范围内；费用和耗时使用f64，保留旧版运算顺序、比较容差、同成本堆顺序和121边边界。
- 线网图通过WeakMap按图对象缓存编码；WASM只拥有当前激活图，切换图会重新装载。每次搜索刷新票价，支持同一图对象下原地调整票价。
- Rust接受状态使用前驱索引；堆/最优表在单次搜索结束后释放。返回结果复制到调用方拥有的紧凑数组，随后释放Rust输出。缓存结果不持有native句柄，不依赖FinalizationRegistry；后续搜索、内存增长和实例重建不会使旧结果失效。
- 寻路组与策略沿用MAP40的LRU预算。单个WASM实例的线性内存最大256MiB；搜索完成并复制结果后，超过64MiB即重建实例。它控制该实例的高水位，不代表浏览器总内存上限，也不压缩正在执行的大搜索。Worker超时回收继续沿用原协议。
- 初始化失败展示错误和重新加载按钮；后台计算失败保留上次成功预测。错误实例回收后可重新装载。404、损坏二进制、ABI不匹配都按失败处理，避免悄悄产生空客流。

公开文件为 `rail/wasm/rail-routing-v1.wasm`，加载使用版本查询参数41。诊断侧栏显示Rust/WASM后端与需求线程线性内存；页面JS堆与WASM线性内存是不同口径。

## 构建与发布

```sh
rustup toolchain install 1.99.1 --profile minimal --target wasm32-unknown-unknown
node scripts/build_rail_wasm.cjs
node scripts/build_rail_wasm.cjs --check
node scripts/run_rail_tests.cjs
```

构建脚本先运行Rust单元测试，再发布优化编译；`--check`逐字节核对提交的WASM。GitHub Actions在全部Node回归之前执行同样的源码/产物检查，任何不一致停止发布。静态分发只需WASM和JS，不要求玩家安装Rust或桌面应用。源码与Cargo.lock保存在仓库，target构建目录忽略。

当前二进制：43931字节；SHA256 `71edade08379475e8e9eb488f786da23093bc33c65b46e679393d26d0eca124a`。在不同绝对目录重新编译，二进制逐字节一致。

## 验证与测量

`test_rail_map41.cjs` 对照2965组完整寻路树：普通/快车/跨线/环线、五种时间价值、首段方向约束、不可达、等成本、原地票价调整、多段票价边界、121边限制、旧版公司与直通折扣。路径、边身份、票价、耗时、费用分成均使用deepEqual，不以误差范围放宽。10条线/25站/6000组出行的完整需求结果与MAP40相等，仅剔除计算耗时和诊断元数据。

额外测试：跨图切换、旧结果缓冲区所有权、连续重建实例、陷阱后恢复、404/损坏/ABI失败与重试、原生模块无导入、生产目录无旧搜索实现。MAP34 Worker回归使用真实WASM异步初始化，保留诊断版本协议、9MB存档和失败隔离测试。

可复现寻路基准：

```sh
node scripts/benchmark_rail_wasm.cjs
node --expose-gc --max-old-space-size=512 scripts/stress_rail_memory.cjs
```

14条线/49站、36组起点与时间价值、所有目的地、相同LRU预算；预热后3次中位数，分别在独立Node进程运行：

| 指标 | MAP40 JS | MAP41 Rust/WASM |
| --- | ---: | ---: |
| 寻路任务中位耗时 | 281.8ms | 49.8ms |
| 路径边校验和 | 31692 | 31692 |
| 进程峰值RSS | 119.61MiB | 56.57MiB |
| 最终缓存组数 | 12 | 12 |

该任务约快5.7倍，包含ABI编码/结果还原开销；不代表游戏FPS或整页速度。WASM使用1.56MiB线性内存，调用方结果数组存活增量约1.18MiB，JS堆增量接近零（GC噪声-0.05MiB）；MAP40存活JS堆增量约0.84MiB。内存迁移到ArrayBuffer/WASM后，单看JS堆会低估实际占用；不同指标不可直接相加推算浏览器总内存。

12个游戏小时、10线25站、6000出行组合、每小时重算与JSON恢复：生成6168、完成6044，乘客守恒；GC后堆首小时25.99MiB、第12小时26.58MiB，进程峰值RSS276.62MiB。它验证连续性，不是整页OOM消除证明。

浏览器验收使用独立合成存档，检查大湾区导入、运行、运营中心、后台重算、导出与重载，以及东京启动；不将QA存档或测试页面发布。

## 分步迁移方向

1. 已完成：寻路、路径费用与换乘决策。
2. 需求核心：分区、OD、接驳、方式/路径选择与容量分配；继续逐字段对照，再删除旧实现。
3. 运行核心：游戏时钟、列车、乘客群组、排队与换乘；状态由Rust唯一持有，前端接收摘要和可视增量。
4. 城市与经营：城市生长、满意度、线路/车辆规则、财务与统计；版本化存档升级与旧档恢复作为每批门槛。
5. 最终边界：JS保留地图/界面、浏览器输入、文件与IndexedDB桥接；核心规则和状态在Rust。每批独立测精确性、运行连续性、内存及失败恢复，避免双份权威状态长期并存。
